深入 Coq 11：存在性证明与构造见证

Created2026-08-09|Updated2026-08-24|计算理论
|Word Count:2.8k|Reading Time:10mins|Post Views:

存在性命题断言某个满足特定性质的对象存在。在 Coq 的命题即类型对应中，证明 ∃ x, P x 等价于构造一个依值对 ⟨w, p⟩，其中 w 是具体见证项，p : P w 是该见证满足性质的证明。这种"构造即证明"的机制直接决定了存在性证明的操作方式。

存在性命题的底层结构

Coq 标准库中 ex 的定义如下：

语法糖 ∃ x : A, P x 展开为 ex A (fun x => P x)。构造证明的唯一方式是应用 ex_intro，给出见证 x 和 P x 的证明。tactic 层面的 exists w 等价于 apply ex_intro with (x := w)，然后留下 P w 作为子目标。

想看见证怎么进项里，要在 Qed 之前用 Show Proof.，输出是 ex_intro nat (fun n => n + 2 = 5) 3 eq_refl——见证 3 直接编码在证明项中。Qed 之后改用 Print ex_basic. 是看不到项的：Qed 产生 opaque 常量，Print 只会给出 *** [ ex_basic : exists n : nat, n + 2 = 5 ] 这样的类型行，不给 body。要让 Print 能看到项，得把 Qed 换成 Defined。

exists tactic：显式提供见证

exists w 将当前目标 ∃ x, P x 变换为 P w，见证必须在此处完全给出。

多层嵌套的 exists 可连写为 exists 3, 7，等价于依次调用两次 exists。

eexists：延迟见证填写

当见证依赖后续证明步骤中才能确定的信息时，可用 eexists 引入一个元变量 ?n 占位，待后续约束将其实例化。

lia 能求解线性整数算术，并在过程中对元变量赋值（旧代码里的 omega 在 8.14 已被移除）。整个流程在逻辑上是：先承诺"某个 n 存在"，再由求解器倒推 n 的值。

此处也可直接用 exists [5; 0; 0]，因为见证已经明确。eexists 的价值在于见证依赖中间计算结果时。

econstructor：构造子驱动的存在性

若存在性目标的见证类型是归纳类型，econstructor 自动选择合适的构造子并引入元变量。

econstructor 对于 ex 等价于 eexists，但在更复杂的归纳类型上优势更明显：

econstructor 对 Reachable 的目标会枚举构造子（reach_refl 或 reach_step）并选择能匹配当前目标的那个，行为类似 constructor 但允许留元变量。

refine：带洞的部分证明项

refine t 接受一个带 _ 占位符的证明项，将每个 _ 转变为独立子目标。这在见证复杂、或证明项结构已知但部分细节待填时非常有用。

ex_intro _ 5 _ 中第一个 _ 是谓词（Coq 可推断），5 是见证，第二个 _ 是待证的 P 5。

refine 在处理依值类型（sigT、sig 等，见前置系列《依值类型——从命题逻辑到一阶逻辑》）时尤为关键，因为这些类型的构造子参数之间存在依值关系，直接写项比拼凑 tactic 更清晰：

存在性与析构

证明中常见模式是从假设中析出存在性见证再加以使用：

intros [n Hn] 是 destruct 的模式匹配简写，直接将 ∃ n, n > 5 分解为见证 n 和性质证明 Hn。与 sigT 的 projT1/projT2 相比，Prop 层的存在性在析构时不产生可计算项，只能用于继续证明。

小结

tactic 见证状态 典型场景
exists w 立即固定 见证已知，一步给出
eexists 延迟到元变量实例化 见证由后续 lia 推导
econstructor 延迟，按构造子结构 归纳类型目标，构造子已知
refine 部分固定，洞待填 证明项结构复杂，需精细控制

存在性证明的核心是见证的构造，而非仅仅宣称存在。这与前置系列《命题即类型——Curry-Howard 同构》里"项即证明、类型即命题"的讨论一脉相承。∃ x, P x 的证明项里带着 x 的具体值，所以 Coq 的存在性证明天然可提取出计算内容。
