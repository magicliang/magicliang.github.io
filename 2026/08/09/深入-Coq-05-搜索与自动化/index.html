深入 Coq 05：搜索与自动化

Created2026-08-09|Updated2026-08-26|计算理论
|Word Count:2.9k|Reading Time:11mins|Post Views:

Coq 的自动化 tactic 不是万能的黑盒，而是针对特定目标形状设计的搜索算法。auto 和 eauto 在 hint 数据库上做反向链推导；lia 在线性整数/自然数算术上调用决策程序；ring 和 field 把多项式等式规约到规范形式再比较。了解每个 tactic 的适用边界，才能在恰当的地方放手让机器搜，而不是在它注定失败的地方反复重试。前置阅读：《深入 Coq 02：目标窗口与 tactic 交互模型》和《深入 Coq 03：Gallina 核心语法速查》。

auto 与 hint 数据库

auto 的核心机制是反向链推导（backward chaining）：从当前 goal 出发，匹配 hint 数据库中的引理头部，将 goal 替换为引理的前提，递归直到所有 subgoal 都被 assumption 或 reflexivity 关闭，或达到搜索深度上限（默认 5）。

eauto 与存在变量

eauto 是 auto 的扩展版本，允许在搜索过程中创建存在元变量（evar），在后续 subgoal 中延迟实例化。这使它能处理 auto 无法处理的存在量词和参数尚未确定的目标。

auto 在同一目标上失败，因为它不会引入 evar。

eauto 的代价

eauto 搜索空间比 auto 大得多，相同深度下运行时间可能差一个量级。高度依赖 evar 的搜索还会产生难以调试的失败信息。实践原则：先用 auto，失败且目标含存在量词或需要延迟实例化时再换 eauto。

omega（已移除）与 lia

omega 的历史地位

omega 曾是 Coq 的标准线性整数算术决策程序，处理含加法、减法、常量乘法的整数/自然数等式和不等式。它在 8.12 被标记废弃，8.14 连同四个 * Omega * 选项一并从标准库删除。8.20 里 Omega.v 这个文件已经不存在：Require Import Omega. 报找不到库，直接调用 omega 则是

从 omega 迁移

omega 在 8.20 已经不可用，没法做 A/B 对照，迁移只能靠替换后重新编译来验证。官方给出的迁移指引就是一句「用 lia 代替」。绝大多数 omega 调用直接换名即可通过；失败的情况通常是目标里混进了非线性项，需要先用 ring 或 nia 处理，或者在 lia 之前补一步 simpl 展开定义。

ring 与多项式等式

ring 证明交换环（commutative ring）上的多项式等式，包括 nat、Z、Q、R 以及用户定义的环结构。它把两边都规约到同一规范形式（按字典序排列的单项式之和），再做语法比较。

ring 的成功前提是目标是纯等式且两边都是多项式表达式，不包含假设中的等式。带条件的等式需要先用 rewrite 替换，再交给 ring：

ring_simplify 与 ring_iff

ring_simplify 化简目标中的多项式子表达式，而不要求两边完全相等。ring 也可通过 ring_iff 用于等价命题（<->），但语法稍有不同，通常不如直接 split; intro; ring 简洁。

field 与有理表达式

field 是 ring 在域（field）上的扩展，处理带除法的等式。它在内部调用 ring，并附加非零条件的侧目标。

field 完成后往往留下若干 <> 0 形式的 subgoal，需要手动提供非零证明。这是它与 ring 最显著的差异——ring 对无除法的表达式无副作用，field 必须处理除数。

各 tactic 选用判断

目标形状 优先尝试 备注
命题逻辑，局部假设充足 auto 不够就加深度或 tauto
存在量词，需延迟实例化 eauto 深度大时运行慢
线性整数/自然数算术 lia 非线性先归纳再 lia
交换环多项式等式 ring 含 rewrite 时先替换再 ring
域（含除法）等式 field 注意非零侧目标
无规律的命题 手动 + 局部 auto 自动化做收尾，不做主干
