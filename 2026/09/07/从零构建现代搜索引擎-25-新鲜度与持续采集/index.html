从零构建现代搜索引擎（25）：新鲜度与持续采集

Created2026-09-07|Updated2026-09-06|技术
|Word Count:2.1k|Reading Time:9mins|Post Views:

到目前为止，索引中的文档是一次性灌入的。真实搜索引擎的内容不断变化——新页面发布、旧页面修改、过期页面删除。搜索引擎需要持续追踪这些变化，保持索引的新鲜度。

本篇实现持续采集系统：条件请求避免无谓下载，自适应调度控制抓取节奏，有界队列和背压防止资源耗尽，幂等写入保证重试安全，状态持久化保证重启不丢进度。

HTTP 条件请求机制

HTTP 协议内置了条件请求机制，避免重复下载未变化的内容。

当前局限

  • 单线程采集——高吞吐场景需要多线程 + 线程池
  • 内容指纹用 hashCode——生产环境应使用 SHA-256
  • SQLite 单写者——并发写入需要加锁或换用其他存储
  • 没有 robots.txt 解析——需要增加 RobotsTxtParser

练习

  1. 实现条件请求，对比有条件请求和无条件请求的带宽消耗
  2. 用自适应调度器抓取 10 个 URL，观察间隔变化曲线
  3. 设置 capacity=100 的有界队列，验证背压行为
  4. 模拟抓取 → 重抓 → 404 → 删除的完整生命周期
  5. 杀掉进程后重启，验证抓取状态不丢失
