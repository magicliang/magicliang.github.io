1. OpenFlow Switch Specification 1.3.5, ONF, 2015-03
   https://opennetworking.org/wp-content/uploads/2014/10/openflow-switch-v1.3.5.pdf
   实际读取：§5.2 Flow Table、§5.3 Matching。
   支持的主张：流表项的 match fields 与 priority 共同标识表项；报文选择最高优先级的匹配项；若有多个同最高优先级匹配，被选表项明确为 undefined。§5.3 还说明，控制器未在添加重叠项时使用 OFPFF_CHECK_OVERLAP 才可能形成该情形。
   下载文件 SHA-256：d4b15444769b13bfdbe12e284d20f14c5d16d94d1f72a83f4a923fc66887eac4。

2. P4_16 Language Specification 1.2.5, P4 Language Consortium, released 2024-10-11
   https://github.com/p4lang/p4-spec/blob/P4-16-v1.2.5/p4-16/spec/P4-16-spec.mdk
   实际读取：§7.1.3 The match kind type、§14.2.1.1 Keys、§14.2.1.4.1 Entry priorities。
   支持的主张：核心 match_kind 包含 exact/ternary/lpm，目标架构可增加其他类型；lpm 掩码的连续 1 越多则自动优先级越高；仅含 exact/lpm 字段的表在多前缀匹配时由最长前缀获胜。这是 P4 lpm 语义，不是 OpenFlow 同优先级规则。
   标签源文件 SHA-256：3f05f4d7982bec38adea948647fd9ea989b22daf3dfd6692c6399aa48598811f。

3. P4Runtime Specification, official repository tag v1.4.0, P4.org API Working Group
   https://github.com/p4lang/p4runtime/blob/v1.4.0/docs/v1/P4Runtime-Spec.mdk
   实际读取：§9.1 TableEntry。
   支持的主张：optional/ternary/range 匹配使用非零数值优先级，数值越大优先级越高；客户端必须允许同优先级表项，但同一报文若能匹配多条同优先级项，数据面选择不具确定性。
   版本注记：核查对象是官方仓库 tag v1.4.0；该标签中源文件的 Title Note 仍写作 "version 1.4.0-dev"，因此本记录不把页面标题扩大为另一个发布状态断言。
   标签源文件 SHA-256：4d61dc62dd23dd89b9aa24054200a570f116394752fa2b709a4b993e1ef1d77c。
