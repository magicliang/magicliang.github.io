计算机体系结构 35：独立性能研究

核心问题

矩阵行遍历比列遍历快，能否直接归因为“连续访问更适合缓存”？一个可证伪的性能研究需要保留输入、正确性、编译路径、原始重复样本和替代解释。改变行跨度的 padding 对照尤其重要：逻辑元素数几乎不变，列遍历时间却可能大幅变化。

附件：逐项缺失文件清单和历史文字记录（不是原始 CSV）。指定 macOS 路径无法在当前环境读取；本克隆并无当时的原始 CSV。

范围与证据等级

2026-09-22 的 arm64 macOS 文字记录称使用 Apple Clang 21.0.0，包含 192 个正式样本；这是历史记录，不是当前验证结论。当前 Linux x86-64 克隆缺少 examples/computer-architecture/performance/outputs/ 的原始 CSV、环境及命令文件，无法核对样本数、中位比值或二进制/源码哈希。只能记录文字文件的 SHA-256，不能将其当成数据校验，更不能冒充当前宿主新测量。

历史实验没有 PMU、固定频率、核心绑定或频率与温度数据，宿主是否裸机也未确认。结果不能定位 cache、TLB、预取器或 DRAM 各自贡献。

核心案例：padding 推翻单变量解释

历史文字记录称：O3 的 2048×2048 矩阵中，stride 2048 的列/行配对耗时比中位数为 35.6196；每行增加一个 padding 元素后，stride 变为 2049，比值降到 8.5251。这些比值尚未在当前克隆用原始样本复算。实验设计保持逻辑求和目标不变，改变了物理行跨度。

这个对照否定“总工作集字节数足以解释全部差异”的说法，却没有单独证明 cache set conflict。padding 同时改变地址映射、页内偏移以及预取器看到的模式，需要硬件计数器或更细的控制实验才能拆分机制。

禁止向量化时，小矩阵 64×64 的列/行配对比中位数只有 1.2175。大矩阵结果不能外推为所有尺寸上的固定倍率。O3 的向量化报告还需结合运行分支阅读：行内核进入 SIMD 路径，四个列遍历输入走标量步长加载。

模式：用最小扰动挑战瓶颈假设

padding、对齐和分块实验都能采用这个结构。对照若同时改变多个机制，只能排除旧解释，不能自动确认某个新解释。

验收结果

从仓库根目录运行 python3 examples/computer-architecture/run_batch.py 34-35，因缺累计材料非零退出；缺口记录逐项列出待恢复文件，标记 raw_samples_verified_now=false，并保存历史文字哈希。仅文字包含样本数和比值不能验收本篇；需从原 macOS 工作区恢复 CSV、命令、环境、源码和二进制哈希后，核对 192 条样本的配对顺序、输入、校验和并复算统计。当前没有新的 x86 性能结论。
