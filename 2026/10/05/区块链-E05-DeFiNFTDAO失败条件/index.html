区块链（E05）：DeFi、NFT、DAO 各自在哪一步会失真

Created2026-10-05|Updated2026-10-10|技术
|Word Count:907|Reading Time:2mins|Post Views:
区块链（25）：把 ERC-20 接进托管后，“收到 70”仍要核算强调资产实际到账，区块链（30）：同一组有效交易也能产生不同经济结果强调交易顺序。若合成订单拿 AMM 兑换后的 token 支付，池的价格由储备和协议费用决定；无限滑点或无期限签名会在有效交易中造成坏结果。借贷系统（Aave 等代表入口）增加预言机、抵押率与清算状态；设计前不能只看利率页面。此处讨论机制与失败条件，不做资产建议。 
flowchart LR
  U[用户授权] --> X[AMM/借贷合约: 储备/债权]
  X --> P[预言机/排序/清算]
  U --> N[NFT: token 所有权]
  N --> M[元数据与实际内容/存储]
  U --> G[DAO: 提案/票权/延时执行]
  G --> X

最小恒定乘积 AMM 可写为 x × y = k 的机制入门，但真实交易要计手续费、舍入、流动性进出与是否满足最小输出；NFT 链上 token 可证明约定登记的所有权，不意味着图像文件可获取或持有人拥有所有版权。DAO 投票通过也需检查执行者、时间锁、升级权与紧急暂停，且按 token 计票不保证投票者互相独立。

三种“链上成功”的失真位置

AMM 在假定无手续费、无其他交易、储备各 100 的最小模型中，x 增加 100 后，为保持 xy=10000，y 从 100 降到 50。用户拿到 50，不是因为“100 单位兑换必得 100”；改变储备的同一笔交易本身就改变报价。若交易前有人先买入，按原报价估出的最小输出可能被触发或让用户接受更差结果。只有明确手续费与整数舍入、流动性变动、最小输出和截止条件，才能谈具体协议的损失。借贷再叠加利率累计、抵押价格和清算人执行窗口；一份价格报告签名有效仍可能陈旧。

NFT 可以在链上登记某个 token 的持有人，但图片存储地址可能指向可修改的中心化服务；即便内容哈希固定，也需要有人提供字节，持币更不等于拥有作品的法律权利。DAO 治理投票通过一项升级，也要看执行是否需要延时、谁能取消/暂停、升级会怎样解释原有托管债权。链上票数、实际可执行指令与现实商品履约三者各有失败出口。没有冻结 Uniswap、Aave 或具体治理部署，本篇只以它们作为资料入口，不能称做当前协议实测或投资判断。

练习一：AMM 净储备 x=100, y=100，无手续费假设加入 dx=100 后若仍满足 xy=10000，理论新 y 是多少？答案：50，输出差额 50；真实合约要额外处理费和整数舍入。练习二：NFT 所指服务器文件被删，链上 token 仍存在，能证明图片仍可下载吗？答案：不能，内容地址与可用存储另核对。真实 AMM、凭证与治理失败注入 NOT_RUN。

可迁移原则：组合合约的每条外部依赖都能推翻单合约局部正确性。参考：Uniswap Docs、Aave Docs、ERC-721（版本与合约地址待核）；导航：区块链（E04）：智能钱包、代付与会话权限怎样收回 · E05 · 区块链（E06）：CID、存储证明与能下载交付文件之间差多少。
