如何画和理解轨道图：以 Elasticsearch Query DSL 为例

Created2026-10-10|Updated2026-11-22|技术
|Word Count:4.5k|Reading Time:16mins|Post Views:

{"query":{"bool":{"filter":[]}}} 中的 filter 取空数组。它在轨道图上怎样从 [ 走到 ]？外层的 bool 又是从哪条查询分支进来的？

《查询与检索》用 EBNF（Extended Backus–Naur Form，扩展巴科斯范式）描述这些请求。铁路图（railroad diagram）把规则画成可行走的路径。经过字面量就写下相应字符，遇到非终结符就展开同名规则，走到出口便得到一个实例。

本文用 ::= 定义规则，引号标出终结符，[…] 表示可省略，(…)* 表示重复零次或多次。例如 '"query"' 的外层单引号界定文法字面量，里面的两个双引号原样出现在 JSON 中。走过这个节点，实际写下 "query"，键名是 query，无需反斜杠。规则省略了 JSON 记号之间的空白。不同资料使用的 EBNF 方言略有差别，例如传统 BNF 常以 <QueryClause> 标出非终结符。本文直接用规则名 QueryClause。

词法、句法与文法

lexical 和 syntactic 是两个层级的形容词。词法层从字符流中识别标识符、数字、关键字和标点等 Token；句法层再把 Token 组合成表达式、语句和更大的结构。return return 可以被词法分析器识别成两个关键字 Token，却不一定是合法语句，这正是两个层级的边界。

grammar 是名词，指规定合法形式的一组规则；grammatical 才是对应的形容词，表示某段输入符合这组规则。技术资料中的 syntax 有时泛指一门语言的全部形式结构，有时狭义地只指 Token 之上的句法，因此规范常用 lexical grammar 和 syntactic grammar 分别命名两层规则。

EBNF 是书写 grammar 的记法，而 grammar 定义了 syntax。EBNF 本身不限定终结符必须是哪一层：终结符是字符时，它可以描述词法；终结符是 Token 时，它可以描述句法。例如：

第一条规则描述字符怎样组成标识符，第二条规则描述项和运算符怎样组成表达式。两者都属于 syntax，因为它们只规定输入可以具有哪些合法形式，不解释名字指向什么、类型是否匹配或表达式执行后得到什么结果；这些问题属于名称解析、类型规则和语义。

先分清：轨道图不是流程图

流程图通常描述“先做什么，再做什么”，节点是动作，箭头是时间或控制流。轨道图描述“输入可以长什么样”，节点是终结符、非终结符或辅助控制节点，箭头是合法路径。

query、sort 等顶层成员可以交换书写顺序。沿轨道先写了哪个字段，只影响生成的 JSON 文本顺序。

三个快速判断

判断一张图是不是轨道图，可以看三个地方：

问题 轨道图的答案 流程图的答案
节点表示什么？ 字面量、语法类别或占位符 动作、状态或系统组件
箭头表示什么？ 输入的合法排列方向 时间、控制流或数据流
回路（loop）表示什么？ 同层结构的重复或分隔列表 重试、循环或事件回环

节点是语法符号，箭头是合法输入路径。回路（loop）是图形上的返回路径，通常表达同一层结构的重复；递归则是一个非终结符在展开过程中再次进入自身。若节点是动作、箭头表示先后，才是流程图；若节点是数据对象、箭头表示传递，才是数据流图。

轨道图的节点与轨道

标准铁路图由终结符、非终结符、边界标记和轨道组成。分岔和汇合表示选择，跨过一段轨道的旁路表示可选。

起点和终点

start 和 end 表示一条完整路径的边界。它们不属于输入内容，只告诉读者从哪里开始走、走到哪里算完成。

如果一张图没有清楚的起点，读者不知道哪些节点是必经的；没有清楚的终点，读者也无法判断某个分支是否已经组成了完整结构。

字面量节点

字面量节点表示输入中实际出现的字符。图 1 的圆角框是字面量，直角框是非终结符。沿最短路径只会写下两个大括号，得到 {}。若在图 2 中选择 query 成员，就必须为它的值展开一条 QueryClause 规则，例如：

语法类别节点

QueryClause、TopLevelMember 等名字是非终结符（non-terminal）。从主图的 TopLevelMember 转到成员规则，选择 query 后再读 QueryClause。同一条子句规则既能在根部使用，也能被 bool.must 里的子查询引用。

选择、重复和回到入口

普通分支每次选一条。重复轨道回到同一层的入口，多产生一项。遇到非终结符则进入另一条规则，展开完成再沿原轨道前进。在 bool 的数组里，逗号让数组多一项，每一项也可以继续嵌套查询。

把 Query DSL 规则翻译成轨道

画图先写一份短语法。JSON 只展示一个实例，轨道图要表达一组合法实例，不能直接照着一个 JSON 示例拉箭头。

以下是《查询与检索》采用的同一份简化文法。String 是 JSON 字符串，UInt 是非负整数，NonNegativeNumber 是非负 JSON 数字。这里只画 match、term 的字符串短写等常见形式，每个对象成员名按需写一次。

图 3　从查询子句选择叶子查询或复合查询

图 3 要分两次读。在 QueryClause 轨道上选 LeafQueryClause，可以展开为 {"term":{"status":"open"}}。选 CompoundQueryClause 则转到下一条同名轨道，再选 BoolQueryClause 或 OtherCompoundQueryClause。例如后者可展开为 {"constant_score":{"filter":{"term":{"status":"open"}}}}，其中 filter 接一个查询对象。LeafQueryClause、CompoundQueryClause 等规则名都不会写进 JSON。

查询类型和查询体要成对选择。'"bool"' 后面接 BoolBody，可含子查询，也可写 minimum_should_match 或 boost。'"term"' 在这份文法里接 FieldText，展开到字段名和值就结束。Query DSL 的叶子与复合查询

文法记号 读轨道时怎样处理
::= 左边给轨道命名，右边规定能依次走过哪些节点。
| 从分岔处选一条走到汇合点。
[…] 可以跳过括号里的整段轨道。
(…)* 括号内的轨道可重复零次或多次。
"["、"]" 各写入一个字面方括号，构成 JSON 数组的两个边界。

空数组的旁路画在哪里

图 4　BoolSlotValue 的单对象、空数组和非空数组路径

先在 BoolSlotValue 入口决定是否走数组分支。单对象分支直接展开一个 QueryClause，例如 {"term":{"status":"open"}}。数组分支必须经过 [ 和 ]。可选的是两者之间的整个元素列表，包括第一个元素以及所有“逗号 + 下一项”。

要得到的 JSON 值 从数组入口怎么走
[] 写下 [，走旁路跳过整段列表，写下 ]。
[{"match_all":{}}] 写下 [，经过一个 QueryClause，直接走向 ]。
[{"term":{"status":"open"}},{"match_all":{}}] 经过第一个子句，沿逗号回路再读一个子句，走向 ]。

若旁路只绕过 ("," QueryClause)*，第一个子句就成了必经节点，空数组无路可走。若旁路连同两个字面括号一起绕过，就会允许 "filter": 后面缺少值。逗号应当只在返回下一项的轨道上，因而 [,]、[{"match_all":{}},] 这样的写法都不能通过 JSON 数组语法。

“可选的分隔列表”在图 1 和图 4 中是同一种结构：[X ("," X)*]。图 1 的边界是 { 与 }，X 为对象成员。图 4 的数组边界是 [ 与 ]，X 为查询子句。bool 的 must、filter、should、must_not 共用这条值规则。

非终结符展开：保留入口，另画子轨道

给规则命名，就可以把大图拆开。例如主轨道只画 TopLevelMember，字段名及取值的分支放在图 2 的第二条轨道。图 3 同理，只在第一条轨道上标 CompoundQueryClause，读者选到它才进入第二条轨道。展开结束后回到调用处继续，嵌套时也照此办理。

回路（loop）：重复成员

图 1 和图 2 都保留了空对象旁路。如果选择成员轨道，先经过一个 TopLevelMember；之后每再走一次包含逗号的返回轨道，就增加一个新成员。

分支：选择成员形状

图 2 每次展开 TopLevelMember 只选一个成员。写 "query" 就要接冒号和查询子句，写 "size" 就要接冒号和非负整数。同一对象需要两个成员时，可以在图 1 走一次逗号回路。回路只规定分隔方式，同名键应写一次。

用轨道图定位常见误读

把同级参数看成执行顺序

图上从 query 走到 sort，不表示先执行查询再执行排序。它只表示 JSON 对象可以先写 query，再写 sort。把两个字段交换顺序，仍然可以得到同样结构的请求。

把分支看成同时发生

TopLevelMember 的分支是“选择一个成员形状”。一次经过选择点只能走一条分支；要同时拥有 query 和 size，必须经过带逗号的返回轨道，再展开一次 TopLevelMember。

把递归引用（recursive reference）看成无限循环

图 5 的虚线表示子查询可以再次选择 QueryClause 的任一分支。一旦选择叶子查询，当前分支就结束。复合查询也有不引入子句的形式，例如 {"bool":{}} 或 {"bool":{"filter":[]}} 都没有子查询需要展开。

把占位符当成字面量

遇到 QueryClause 就展开子句，遇到 UInt 就填非负整数。比如文法中的 '"size"' ":" UInt 依次写出键名、冒号和整数，得到 "size": 10。

把代表性分支当成完整清单

图 3 下方的 OtherCompoundQueryClause 用 constant_score 演示另一种复合查询。完整 DSL 还有 dis_max 等类型。叶子查询同理，本例列出 term、match 和 match_all，其余类型可查 Elasticsearch 的查询文档。
